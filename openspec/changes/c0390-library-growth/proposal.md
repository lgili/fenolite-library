# Grow the library to cover the common components

The maintainer wants fenolite-library to hold "almost every component that exists", in two ways that
both stay inside POLICY.md: items authored here under CC0-1.0 from public package dimensions, and items
imported from upstream libraries whose licence the allow-list accepts.

Today the library holds four footprints, two symbols and two devices. This change adds, family by family,
footprints generated by Fenolite's package generators (change c0260 of the core) from parameter tables,
generic symbols per device class, and later imported items from checked upstream libraries.

## What changes

- New authored item folders under `footprints/cc0/<Namespace>/` and `symbols/cc0/<Namespace>/`, one per
  footprint or symbol, each with `item.json`, one record, the generated native outputs, `LICENSE`, `NOTICE`
  and `PROVENANCE.json`. No existing item, board or block changes.
- New D-ids in `sources.toml`, one per datasheet or standard read, in a reserved block starting at
  D-0390, added in their own commits.
- A family table and expander under this change (`families/`), so whole families are produced from one
  table row each, never drawn one by one.
- A licence register of import candidates, with a verdict per source; only sources with a verified
  accepted licence are imported, each in its own licence family folder.

## What does not change

- No push, tag, release or Pages publication: v1.0.0 publication needs the maintainer's separate OK.
- No change to the Fenolite core; missing generators are reported as proposals.
- No material from KiCad's official libraries, SnapEDA, Ultra Librarian, SamacSys/Component Search
  Engine, EasyEDA/LCSC/OSHWLab or any vendor portal whose terms forbid redistribution; no vendor 3D model.
- Evidence stays honest: authored lands are `INFERRED` (calculated) or carry the manufacturer's land as
  read; nothing is marked reviewed without a human review.
